      03 / THE COMPARISON

      More than matching text.

      Each supported fixture pairs foreign source with a hand-authored Carve expectation. The suite checks the structure that text matching would miss.

      1. 01

        Parse & map

        The foreign reader builds its tree. An adapter maps it into Carve's published AST schema.

      2. 02

        Check semantics

        Compare nesting, attributes, destinations, list layout, and code whitespace with the authored expectation.

      3. 03

        Render structure

        Compare foreign HTML with Carve's rendered elements and nesting, after declared normalizations.

      4. 04

        Round trip

        Check Carve source, JSON interchange, and exported foreign source by reading each back.

      Existing importers

      Markdown, HTML, and Djot cases also check Carve's public source importers against the foreign renderer.

      Losses are assertions

      A loss fixture requires a specific diagnostic code, fidelity, and AST path. It also checks schema validity and retained readable content.

      Missing readers fail

      The full sweep requires every target. Narrow selections name unmeasured readers; unavailable executables never become silent skips.

      04 / LIMITS & FINDINGS

      The boundaries stay visible.

      These are subset adapters, not a promise that arbitrary foreign trees fit Carve. New claims need new fixtures.

      Source coordinates & generated structure

      Mapped trees omit foreign source positions and set srcByteLength: 0. Generated section wrappers, heading IDs, and renderer classes are normalized. Authored attributes remain part of the comparison.

      List layout & heading levels

      Docutils has no Carve list-tightness field; its adapter uses loose lists. Asciidoctor's paragraph-wrapped lists follow the same boundary. reStructuredText heading levels depend on the first appearance of adornment styles; isolated or skipped levels receive export diagnostics.

      AsciiDoc inline comparison

      Asciidoctor's block model provides structure, and converted HTML provides inline semantics. A separate DocBook conversion is mapped without the HTML adapter and must match the primary tree. Both outputs share Asciidoctor’s parser; this checks two output paths rather than two independent parsers.

      Unsupported nodes & fields

      Fixtures cover attributes, task state, numbering styles, quote attribution, code metadata, tables, and other nodes outside a target's subset. A loss case passes only when the expected diagnostic is present and readable content survives.

      Djot hard-break writer: upstream fix merged

      The pinned djot.js 0.3.2 writer throws on hard_break. The adapter uses a tested subset writer for those documents and reports foreign-writer-workaround. Upstream PR #158 merged the native fix on October 2, 2026, including regression tests for wrapping and nested prefixes. This report still measures the pinned 0.3.2 release; the workaround remains until the dependency is upgraded.

      Rich tables & Carve source

      JavaScript, PHP and Rust preserve multiple bodies, intermediate headers, empty bodies and per-body row headers through positional source metadata. Decimal width assertions stay exact. Inspect the combined table fixture.

      Section attributes, block cells and short captions remain declared source losses. Span placeholders can lose header flags. The HAST adapter preserves empty bodies through AST interchange; the public HTML importer still drops a leading empty body without a loss diagnostic, tracked in carve-js #2466.

      Source-export edge cases

      Regression fixtures cover adjacent lists, quotes after code or lists, literal syntax markers, escaped text, duplicate link labels, relative destinations, document titles, and code fences containing delimiter-like lines.
